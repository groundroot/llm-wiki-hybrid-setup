# LLM 위키 + 하이브리드 운영 셋업

AI 에이전트가 옵시디언 볼트를 "LLM 위키"로 운영하게 만드는 셋업 패키지다. Karpathy의 LLM 위키 패턴 위에, 에이전트 작업 볼트와 사용자 옵시디언 볼트를 나누어 돌리는 **하이브리드 운영** 방식을 얹었다.

## 가장 빠른 시작 (Muse 사용 중이라면)

파일을 손으로 복사할 필요 없이, **[Muse 세팅 프롬프트](SETUP-PROMPT.md)**를 복사해 Muse에 붙여넣으면 에이전트가 볼트 생성부터 동기화·자동 작업까지 알아서 세팅한다. 수동으로 구축하고 싶으면 아래 적용 순서를 따르면 된다.

## 이 셋업이 무엇인지

보통의 RAG는 질문할 때마다 원본 문서에서 조각을 다시 찾아내므로 지식이 쌓이지 않는다. LLM 위키는 다르다. 에이전트가 원본 소스를 읽고 **링크된 마크다운 위키로 컴파일**해 두며, 새 소스가 올 때마다 기존 페이지를 갱신해 종합을 유지한다. 지식은 질문할 때마다 재도출되는 게 아니라 한 번 컴파일되어 계속 최신으로 관리된다.

여기에 이 패키지는 한 가지를 더한다: **볼트를 두 개로 나누는 것**이다.

- 에이전트는 24시간 돌아가는 작업 공간(서버, VM, 에이전트 런타임)이 필요하다. 자동 리서치와 유지보수는 사용자 컴퓨터가 꺼져 있어도 돌아야 한다.
- 사람은 자기 옵시디언 볼트에서 노트를 읽고, 쓰고, 그래프로 탐색하고 싶어 한다.

그래서 에이전트 작업 볼트와 사용자 옵시디언 볼트를 나누고, 하루 한 번 서로 동기화한다. 자동 작업은 에이전트 쪽에서 쉬지 않고 돌고, 사용자는 자기 볼트에서 완성된 위키를 바로 본다.

## 왜 하이브리드인가

| 방식 | 장점 | 단점 |
|---|---|---|
| 에이전트 볼트만 | 자동 작업이 끊기지 않음, 에이전트가 전체를 통제 | 사람이 열 일이 없어 위키가 죽은 문서가 되기 쉬움 |
| 사용자 볼트만 | 옵시디언으로 바로 보고 탐색 가능, 그래프·백링크 활용 | 컴퓨터가 꺼지면 자동 작업 정지, 에이전트 작업 노트로 자기 볼트가 어지러워짐 |
| **하이브리드 (이 패키지)** | 자동 작업은 에이전트 쪽에서 계속, 사람은 자기 볼트에서 완성본 열람 | 동기화 규칙을 명확히 해야 함 (단방향 2회로 단순화) |

원칙은 간단하다: 에이전트 볼트에서 일하고, 사용자 볼트의 전용 폴더(예: `LLM 위키/`)에는 완성된 페이지만 복사한다. 사용자 볼트의 나머지는 읽기 전용이다.

## 전체 구조

```
llm-wiki-hybrid-setup/
├── README.md                  # 이 문서
├── LICENSE                    # MIT
├── vault-template/            # 그대로 옵시디언 볼트로 열 수 있는 빈 볼트 템플릿
│   ├── .obsidian/app.json     # 첨부=raw/assets, 새 노트=00 받은편지함 프리셋
│   ├── 홈.md                  # 볼트 입구
│   ├── index.md               # 위키 전체 카탈로그 (에이전트가 유지)
│   ├── log.md                 # append-only 활동 로그
│   ├── raw/                   # 원본 소스 (불변)
│   │   └── assets/            # 첨부 이미지
│   ├── 00 받은편지함/          # 아직 정리 안 된 메모
│   ├── 10 위키/               # 위키 페이지 (핵심)
│   ├── 20 사람/               # 사람 페이지
│   ├── 30 프로젝트/           # 프로젝트 페이지
│   ├── 90 아카이브/           # 끝난 것들
│   ├── _템플릿/               # 위키페이지·사람·프로젝트 템플릿
│   └── _시스템/
│       ├── 운영규칙.md         # 스키마 (에이전트 행동 규칙)
│       ├── 지속발전 주제.md    # 계속 발전시킬 주제 목록
│       ├── 스킬 후보.md        # 반복 패턴 → 스킬 후보
│       └── 볼트점검상태.예시.json
├── skills/
│   └── vault-daily-review/
│       └── SKILL.md           # 볼트 데일리 리뷰 + 동기화 스킬
└── automation/
    ├── daily-research.md          # 매일 리서치 예시
    ├── topic-sweep.md             # 정기 주제 스윕 예시
    └── vault-review-and-sync.md   # 데일리 리뷰 + 동기화 예시
```

볼트 내부의 핵심은 3층이다.

1. **Raw sources (`raw/`)** — 원본 자료. 불변. 진실의 원천.
2. **Wiki (`10 위키/` 등)** — 에이전트가 생성·유지하는 마크다운 층.
3. **Schema (`_시스템/운영규칙.md`)** — 구조와 워크플로를 정의하는 문서. 에이전트를 "위키 관리자"로 만드는 설정 파일이다.

## 설치/적용 순서

### 1. 볼트 복사

`vault-template/`를 원하는 위치에 복사하고, 옵시디언에서 "폴더를 볼트로 열기"로 연다. 에이전트 작업 볼트와 사용자 볼트 두 곳에 각각 두는 것이 하이브리드 운영의 기본이다.

```bash
cp -r vault-template ~/my-agent-wiki      # 에이전트 작업 볼트
cp -r vault-template ~/my-obsidian-wiki   # 사용자 옵시디언 볼트 안의 전용 폴더로 써도 됨
```

### 2. 스키마를 자기 도메인에 맞게 수정

`_시스템/운영규칙.md`를 열어 다음을 자기 상황에 맞게 고친다.

- 볼트의 주제/도메인 (무엇에 대한 위키인가)
- 폴더별 사용법과 페이지 형식
- 프론트매터 필드
- "지속 발전 주제"의 지정 방식

이 문서가 곧 에이전트의 행동 규칙이다. 처음부터 완벽할 필요 없다. 한 달쯤 쓰면서 에이전트와 함께 다듬는 것이 전제다.

### 3. 스킬 배치

`skills/vault-daily-review/SKILL.md`를 에이전트의 스킬 디렉터리에 복사하고, 문서 안의 플레이스홀더를 실제 값으로 바꾼다.

- `<USER_VAULT_PATHS>`: 사용자 볼트 경로들
- `<WIKI_VAULT_PATH>`: 에이전트 작업 볼트 경로
- `<SKILLS_DIR>`: 스킬 디렉터리

### 4. 자동 작업 예시 연결

`automation/`의 예시 3개 중 필요한 것을 골라 스케줄러(크론 등)에 등록한다.

1. **매일 리서치** (`daily-research.md`): 변화가 잦은 주제 1개를 매일 업데이트
2. **주제 스윕** (`topic-sweep.md`): 여러 주제를 주 2회 정도 한 번에 훑기
3. **데일리 리뷰 + 동기화** (`vault-review-and-sync.md`): 사용자 볼트의 새 노트를 에이전트 위키로 통합하고, 완성 페이지를 사용자 볼트로 내보내기 (하이브리드의 핵심)

각 문서에 크론 본문으로 바로 쓸 수 있는 프롬프트 예시가 코드블록으로 들어 있다.

## Karpathy 패턴과의 차이

원본 패턴: [Karpathy의 llm-wiki gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

이 패키지가 원본에 더하거나 바꾼 것:

- **하이브리드 2-볼트 운영**: 원본은 볼트 하나를 전제한다. 이 패키지는 에이전트 작업 볼트 + 사용자 옵시디언 볼트로 나누고, 동기화를 "새 노트 가져오기"와 "완성 페이지 전용 폴더로 내보내기"라는 단방향 2회로 고정했다.
- **지속 발전 주제 레지스트리**: 사용자가 지정한 주제를 일회성 페이지로 끝내지 않고, 새 소스가 올 때마다 계속 보강하는 운영 장치(`_시스템/지속발전 주제.md`)를 명문화했다.
- **자동 리서치 작업 예시**: 매일 리서치/주제 스윕 같은 스케줄 작업을 프롬프트 예시와 함께 패키지로 포함했다.
- **스킬 승격 파이프라인**: 데일리 리뷰에서 발견한 반복 패턴을 `_시스템/스킬 후보.md`에 쌓고, 조건이 되면 실제 스킬로 만드는 흐름을 스킬 문서에 넣었다.
- **기본 레시피 제공**: 폴더 구조, 템플릿, `index.md`/`log.md` 형식, 옵시디언 프리셋까지 빈 템플릿으로 제공해 바로 시작할 수 있게 했다.

원본의 핵심(raw 불변, 위키는 에이전트가 유지, 좋은 답변은 위키에 파일링, 주기적 lint)은 그대로 따른다.

## 주의사항

- **비밀값 금지**: 비밀번호, 인증번호, 카드번호, API 키, 웹훅 URL 같은 비밀값은 위키에 절대 기록하지 않는다. 소스에 섞여 있어도 옮기지 않는다.
- **raw는 불변**: `raw/`의 원본은 절대 수정하지 않는다. 요약·해석은 위키 층에서만 일어난다.
- **사용자 볼트는 읽기 전용**: 동기화 전용 폴더 밖의 사용자 파일을 에이전트가 수정·삭제하지 않는다.
- **불확실한 것은 미확인으로**: 추정을 사실로 쓰지 않는다. 노트 기반 내용은 출처를 밝힌다.
- **정기 리서치는 승인 후에**: 스케줄 작업은 사용자가 주제와 주기를 승인한 것만 돌린다.
- 이 볼트는 기본적으로 로컬 전용이다. 클라우드 동기화는 본인 판단으로 선택한다.
