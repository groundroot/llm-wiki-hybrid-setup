# LLM 위키 운영 규칙 (스키마)

이 문서가 이 볼트의 스키마다. AI 에이전트는 세션이 바뀌어도 이 규칙대로 위키를 유지한다.
구조는 Karpathy의 LLM 위키 패턴을 토대로 한다: raw 소스 / 위키 / 스키마 3층.

> 적용 전 할 일: 이 문서를 통째로 읽고, 당신의 도메인(주제, 폴더 사용법, 페이지 형식)에 맞게 고쳐라. 이 문서가 곧 에이전트의 행동 규칙이 된다.

## 3층 구조

1. **Raw sources (`raw/`)**: 당신이 모아 온 원본 자료(글, 문서, 이미지, 데이터). **불변이다. 절대 수정하지 않는다.** 진실의 원천. 첨부 이미지는 `raw/assets/`.
2. **Wiki (`10 위키/`, `20 사람/`, `30 프로젝트/`)**: 에이전트가 생성·유지하는 마크다운 층. 요약, 개념, 엔티티, 비교, 종합 페이지. 당신은 읽고 에이전트가 쓴다.
3. **Schema (이 문서)**: 구조, 규약, 워크플로를 정의한다. 당신과 에이전트가 함께 진화시킨다.

특수 파일:
- **`index.md`** (루트): 위키 전체 카탈로그. 카테고리별로 페이지 링크 + 한 줄 요약. 모든 ingest 때 갱신한다.
- **`log.md`** (루트): 시간순 append-only 기록. 항목 형식은 `## [YYYY-MM-DD] 종류 | 제목` (종류: ingest / query / lint / setup). 최근 기록은 `grep "^## \[" log.md | tail -5`로 본다.

## 핵심 원칙

1. **위키는 복리로 쌓이는 산출물이다**: 새 소스가 오면 그냥 인덱싱하지 않고, 읽어서 기존 페이지들에 통합한다 — 엔티티 갱신, 주제 요약 개정, 모순 표시, 종합 강화.
2. **질문 → 답변 → 위키 저장**: 질문에 답할 때는 먼저 `index.md`를 읽고 관련 페이지를 찾아 출처와 함께 답한다. 좋은 답(비교, 분석, 새로 발견한 연결)은 채팅으로 흘려보내지 말고 위키 페이지로 파일링한다. 일회성 확인·잡담·실시간 상태 조회는 저장하지 않는다.
3. **명시 지시는 무조건 저장**: "위키에 넣어줘", "저장해줘"라고 하면 저장한다.
4. **링크가 본체다**: 페이지끼리 `[[위키링크]]`로 연결한다. 없는 페이지를 가리키는 링크(dead link)는 만들지 않는다.
5. **중복 금지·모순 명시**: 같은 주제 페이지가 있으면 새로 만들지 않고 갱신한다. 새 자료가 기존 내용과 충돌하면 최신 확인 사실을 우선하되 충돌 사실을 페이지에 표시한다.
6. **불확실성 표시**: 출처가 불확실한 것은 "미확인"으로 표시한다. 추정을 사실로 쓰지 않는다.

## 작업 1: Ingest (소스 투입)

당신이 소스를 주면(파일, 링크, 붙여넣기) 다음 순서로 처리한다:

1. 소스를 `raw/`에 원본 그대로 저장한다(웹 글이면 마크다운으로 변환해 저장, 원본 URL 명시). 이미지는 `raw/assets/`에.
2. 소스를 읽고 핵심 takeaway를 사용자와 짧게 확인한다(무엇을 강조할지).
3. `10 위키/`에 소스 요약 페이지를 만든다(형식은 아래 페이지 형식 참조, 출처에 raw 파일 링크).
4. 관련된 기존 엔티티·개념·주제 페이지를 찾아 갱신한다. 하나의 소스가 여러 페이지를 건드리는 게 정상이다.
5. `index.md`에 새·갱신 페이지를 반영한다.
6. `log.md`에 `## [YYYY-MM-DD] ingest | 소스 제목` 항목을 append 한다.

## 작업 2: Query (질문)

1. `index.md`를 먼저 읽고 관련 페이지를 찾는다. 규모가 커지면 파일명·본문 검색(rg)을 병행한다.
2. 관련 페이지를 읽고 출처를 밝혀 답한다.
3. 답이 재사용 가치가 있으면(비교표, 분석, 종합) 새 위키 페이지로 저장하고 index와 log(`query`)에 남긴다.

## 작업 3: Lint (건강검진)

요청하거나 주기 점검 때 다음을 확인한다:

- 페이지 간 모순, 새 소스에 밀려 낡은 주장
- 들어오는 링크가 없는 고립 페이지(orphan)
- 자주 언급되는데 전용 페이지가 없는 중요 개념
- 빠진 상호참조, 웹 검색으로 채울 수 있는 빈틈
- 조사해볼 만한 새 질문·소스 제안

결과를 보고하고, 고칠 것은 고친 뒤 log에 `lint` 항목을 남긴다.

## 페이지 형식

파일명: 주제를 드러내는 짧은 제목 (예: `예시 주제 페이지.md`)

프론트매터:

```yaml
---
유형: 위키 | 소스요약 | 사람 | 프로젝트
주제: []
만든날: YYYY-MM-DD
갱신날: YYYY-MM-DD
출처: 대화 / raw 파일명 / URL
---
```

본문: 한 줄 요약 → 핵심 내용 → `## 연결`(관련 페이지 링크) → 변경 이력.

- 사람: `20 사람/<이름>.md` — 관계, 역할, 최근 맥락. 개인정보 과다 기록 금지.
- 프로젝트: `30 프로젝트/<이름>.md` — 목표, 현재 상태, 결정 사항, 다음 행동.

## 지속 발전 주제 (사용자 지정)

- 지정 주제 목록은 [[_시스템/지속발전 주제]]에서 관리한다. 추가·삭제는 사용자 지시로만.
- 지정 주제는 새 소스·새 사실이 들어올 때마다 관련 페이지를 계속 보강한다. 보강 시 기존 내용을 지우지 말고 추가하고 `갱신날`을 갱신한다.
- 정기 리서치는 사용자가 승인한 일정·주제로만 한다.

## 금지 사항

- 비밀번호, 인증번호, 카드번호, API 키, 웹훅 URL 같은 비밀값은 절대 기록하지 않는다.
- `raw/`의 원본은 절대 수정하지 않는다.
- 사용자 승인 없이 볼트 내용을 외부로 보내지 않는다.
