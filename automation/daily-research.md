# 자동 작업 예시 1: 매일 리서치 (데일리 업데이트)

특정 주제 하나를 매일 조사해 위키 페이지를 최신 상태로 유지하는 자동 작업이다. 공식 업데이트·새 기능처럼 변화가 잦은 주제에 적합하다.

## 전제

- 대상 주제가 `<WIKI_VAULT_PATH>/_시스템/지속발전 주제.md`에 등록되어 있고, 대응하는 위키 페이지가 있다.
- 스케줄러(크론 등)에 아래 프롬프트를 등록하고 매일 1회 실행한다. 실행 시각은 사용자가 자료를 확인하기 좋은 시간(예: 아침)으로 잡는다.

## 크론 본문 프롬프트 예시

```text
매일 1회, 지정 주제를 리서치해서 LLM 위키를 업데이트하는 작업이다. 이 위키는 raw/wiki/schema 3층 패턴으로 운영된다.

대상 주제: (예: 내가 쓰는 도구의 활용법)
대상 페이지: <WIKI_VAULT_PATH>/10 위키/<주제 페이지>.md

작업 순서:
1. 스키마 <WIKI_VAULT_PATH>/_시스템/운영규칙.md, 인덱스 <WIKI_VAULT_PATH>/index.md, 대상 페이지를 읽어 현재 상태와 중복 여부를 파악한다.
2. 웹에서 해당 주제의 새 내용을 조사한다: 공식 업데이트·새 기능, 공식 문서의 활용 가이드, 커뮤니티(포럼, SNS, 블로그)에 공개된 실제 활용 사례와 팁.
3. 확인된 것만 위키에 추가한다. 출처 URL과 확인 날짜를 각 항목에 붙이고, 검증 안 된 것은 넣지 않거나 "미확인"으로 표시한다. 기능·가격 같은 사실은 공식 문서나 실제 페이지에서 확인한 것만 쓴다. 참고한 원본 글은 가능하면 <WIKI_VAULT_PATH>/raw/에 마크다운으로 저장하고(원본 URL 명시), 위키 항목에서 그 소스를 출처로 건다. raw/의 기존 파일은 절대 수정하지 않는다.
4. 대상 페이지의 적절한 섹션에 새 항목을 날짜와 함께 추가하고 프론트매터의 갱신날을 오늘로 바꾼다. 새 위키 페이지를 만들었으면 루트 index.md에 링크와 한 줄 요약을 추가한다.
5. <WIKI_VAULT_PATH>/log.md에 `## [YYYY-MM-DD] ingest | <주제> 리서치` 형식으로 무엇을 추가했는지 append 한다.
6. 보고는 짧게: 오늘 추가한 항목 제목 3~5개 수준. 새로 확인할 만한 게 없으면 "오늘은 새 업데이트 없음"이라고만 알린다.

금지: 외부로 메시지를 보내지 않는다. 비밀값(비밀번호, 토큰, 카드번호 등)은 위키에 절대 기록하지 않는다. 확실하지 않은 내용을 사실처럼 쓰지 않는다.
```

## 운영 팁

- 보고가 매일 오면 피로해진다. "새 항목이 있을 때만" 보고하도록 하거나, 주말에 몰아서 보도록 조건을 조정하라.
- 주제를 여러 개 매일 돌리면 비용이 커진다. 매일 리서치는 1~2개 주제까지가 적당하고, 나머지는 [주제 스윕](topic-sweep.md)으로 돌리는 게 낫다.
