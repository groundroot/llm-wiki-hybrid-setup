# 자동 작업 예시 3: 볼트 데일리 리뷰 + 동기화 (하이브리드 운영)

사용자의 옵시디언 볼트(사람이 직접 쓰는 볼트)에서 새 노트를 감지해 에이전트 작업용 위키에 통합하고, 완성된 위키 페이지를 다시 사용자의 옵시디언 볼트로 내보내는 하이브리드 운영의 핵심 자동 작업이다.

## 하이브리드 구조

두 개의 볼트가 역할을 나눈다.

- **에이전트 작업 볼트** (`<WIKI_VAULT_PATH>`): 에이전트 서버/작업 공간에 있다. 자동 리서치, ingest, 위키 유지보수가 여기서 일어난다. 사람이 직접 열 일은 거의 없다.
- **사용자 옵시디언 볼트** (`<USER_VAULT_PATH>`): 사용자의 기기에 있고, 사용자가 옵시디언으로 직접 보고 편집하는 볼트다. 에이전트는 **읽기 전용**으로 접근한다.

흐름은 단방향 두 번이다.

1. **가져오기(import)**: 사용자 볼트의 새 노트·수정한 노트를 감지해 에이전트 위키에 통합한다.
2. **내보내기(export/sync)**: 에이전트 위키에서 완성·갱신된 페이지를 사용자 볼트의 전용 폴더(예: `LLM 위키/`)에 복사한다. 사용자 볼트의 나머지 영역은 절대 건드리지 않는다.

이렇게 나누면 자동 작업은 사용자 기기가 꺼져 있어도 에이전트 쪽에서 계속 돌고, 사용자는 자기 옵시디언에서 완성된 위키를 바로 읽고 그래프로 탐색할 수 있다.

## 전제

- `vault-daily-review` 스킬이 배치되어 있다 ([../skills/vault-daily-review/SKILL.md](../skills/vault-daily-review/SKILL.md)).
- 사용자 볼트 안의 동기화 전용 폴더명을 정한다(예: `LLM 위키`).
- 에이전트가 사용자 기기의 파일에 접근할 수 있다(기기 연동, SSH, 또는 클라우드 동기화 폴더 경유).

## 크론 본문 프롬프트 예시

```text
매일 1회, 사용자 옵시디언 볼트들을 점검하고 하이브리드 동기화를 수행하는 작업이다. 스킬 vault-daily-review(<SKILLS_DIR>/vault-daily-review/SKILL.md)의 워크플로를 그대로 따라라.

핵심만 요약하면:
1. 스킬 파일과 위키 스키마(<WIKI_VAULT_PATH>/_시스템/운영규칙.md), 상태 파일(<WIKI_VAULT_PATH>/_시스템/볼트점검상태.json)을 먼저 읽는다.
2. 사용자 기기에 접근할 수 없으면(오프라인 등) 조용히 종료하고 짧게만 보고한다.
3. 사용자 볼트들을 3단계 깊이까지 순회해 신규·변경된 `.md` 노트를 상태 파일과 비교해 찾는다(최대 20개/회, 최신순).
4. 노트를 읽고 에이전트 위키(<WIKI_VAULT_PATH>)에 ingest 규칙대로 통합한다. 반복 사용 가능한 패턴은 _시스템/스킬 후보.md에 기록하고, 패턴이 반복되거나 절차가 명확하면 실제 스킬로 만든다.
5. 이번 실행에서 에이전트 위키에 새로 생기거나 갱신된 페이지를 사용자 볼트의 동기화 전용 폴더 <USER_VAULT_PATH>/LLM 위키/ 아래에 같은 구조로 복사한다. 동기화 전용 폴더 밖의 사용자 파일은 절대 수정하지 않는다.
6. index.md, log.md(`## [YYYY-MM-DD] ingest | 볼트 데일리 리뷰`), 상태 파일을 갱신한다.
7. 보고는 짧게: 새 노트 수, 통합한 내용, 동기화한 페이지, 만든 스킬/후보. 새 노트 없으면 한 줄.

금지: 동기화 전용 폴더 이외의 사용자 파일 수정·삭제 금지. 비밀값이 담긴 파일(credential, .env 등)은 읽지 않고, 노트에서 본 비밀값은 위키에 옮기지 않는다. 외부 전송 금지.
```

## 주의사항

- 동기화 방향을 반드시 구분하라. 사용자 볼트 → 에이전트 위키는 "새 노트 감지·통합", 에이전트 위키 → 사용자 볼트는 "전용 폴더에 복사"만 허용한다. 양방향 병합은 충돌과 데이터 손상 위험이 크다.
- 사용자가 전용 폴더 안의 페이지를 직접 고치는 경우를 허용할지 미리 정하라. 허용하면 다음 동기화에서 덮어쓰지 않도록, 복사 전에 수정 시각을 비교하는 규칙을 스킬에 추가해야 한다.
- 첫 실행 때는 기존 노트 전체가 "신규"로 잡힌다. 상태 파일을 미리 채워 두거나, 첫 실행의 처리 상한(예: 20개)을 감안해 며칠에 나눠 따라잡게 하라.
